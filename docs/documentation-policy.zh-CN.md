# 文档维护与提交范围

本规则适用于说明文档，不限制正常提交相关源码、源码内学习注释、测试、依赖锁文件、构建配置与第三方许可声明。

| 类别 | 内容 | Git处理 |
| --- | --- | --- |
| 更新日志 | 版本变化、修复、兼容与已知限制 | CHANGELOG及releases，正常提交 |
| 正式技术记录 | 实际架构、协议、契约、运行边界、实现及真实验证 | docs中的现状、规范和技术记录，正常提交 |
| 历史技术记录 | 对应阶段的实现/设计 | 可以保留，明确日期和历史范围，链接当前规范 |
| 学习报告 | 教学、代码导读、学习路线、练习和个人学习汇编 | 本地保存，不提交 |
| 应用对照/探索 | 其他应用比较、社区调查、未实施路线和研究结论 | 本地保存，不提交 |
| 混合稿 | 实现说明与独立学习、对照或研究章节混杂 | 原稿留本地，技术事实汇总到独立规范/更新记录 |
| 原始证据 | 日志、截图、API回执、数据库、个人工作文件 | 本地隔离保存，不提交 |

按正文和主要用途判断，不以机器目录名、单个“比较”字眼或官方API引用误判。修改一条链接或包含代码索引，不自动使正式技术记录变成学习报告。

公开文档入口为README、docs/README、current-state、runtime-contracts、known-issues和windows-release。不得依赖仅存在于维护者本地的学习/探索稿，否则新克隆会产生断链。链接历史文档时注明历史范围。

本地报告可放仓库外或被忽略的docs/local、docs/learning、docs/research。已有混合稿的精确忽略条目维护在.gitignore；取消跟踪使用仅索引操作并保留磁盘原文。不得因文档整理删除用户源码或学习注释。

从新提交取消跟踪，不会清除旧提交、标签、分叉或远程缓存。普通后续提交推送只更新分支当前文件树；清除历史需要单独明确授权并评估影响。本规则不提供推送、强制推送、标签或发布的默认授权。
