# 文档分类与维护规则

本规则约束说明文档；相关源码、源码内学习注释、测试、锁文件、构建配置与第三方许可声明正常提交。

## 公开文档

| 类别 | 位置 | 内容 |
| --- | --- | --- |
| 产品与社区入口 | 根README、CONTRIBUTING、SECURITY、CODE_OF_CONDUCT、LICENSING及第三方声明 | 产品用途、启动、贡献、安全与授权事实 |
| 更新日志 | CHANGELOG.md | 版本变化、修复、兼容和限制；未发布变化放Unreleased |
| 当前技术规范 | docs/current-state、runtime-contracts、known-issues、windows-release | 实际架构、契约、边界、已知问题与构建发布流程 |
| 源码变化汇总 | docs/changes/ | 已实现变化、验证范围与限制 |
| 技术实现记录 | docs/records/ | 按主题记录实现、诊断、设计取舍及真实验证 |
| 历史版本说明 | docs/releases/ | 对应版本已发布能力与实际资产 |

已有历史技术记录保留原地址，由[记录索引](records/README.zh-CN.md)分类。日期和历史适用范围必须明确，不能用旧计划、测试总数或构建状态覆盖当前实现。新记录建议命名`YYYYMMDD-topic.zh-CN.md`，同步相关索引。

## 仅本地资料

| 类别 | 建议位置 | 处理 |
| --- | --- | --- |
| 学习、代码导读、学习路线和练习 | docs/local/learning/或仓库外 | 不提交 |
| 其他应用对照、社区调查、探索与未实施路线 | docs/local/research/或仓库外 | 不提交 |
| 个人交接与AI会话汇编 | docs/local/handoffs/或仓库外 | 不提交 |
| 技术/学习/对照混合稿 | docs/local/notes/或仓库外 | 原稿留本地；公开技术事实单独整理 |
| 原始证据、日志、截图、API回执、数据库和个人文件 | 被忽略的本地输出目录 | 不提交 |

旧本地报告保留原文件名和相互链接，具体路径由.gitignore排除；本地分类入口放在被忽略的docs/local下。不要为整理分类删除原文、源码注释或用户文件。对混合稿按正文及用途判断，不仅凭文件名；必要的第三方API文档、组件来源和许可引用不属于应用比较。

## 链接与持续维护

1. 公开Markdown使用仓库相对链接和真实章节锚点，图片及链接目标须在提交树中存在；不得依赖仅在本机存在或被忽略的报告、证据和生成产物。
2. 保持README → docs入口 → 当前规范/技术记录/版本说明可连续导航。技术记录链接有关前序事实，历史设计明确链接当前规范。
3. 修改路径前检查所有入链；优先保留既有地址。若必须移动，同批修复入链，并核对本地报告引用。
4. 技术记录写清问题、实际变化、兼容/恢复、真实验证和未覆盖范围。公开内容不包含机器个人目录、原始聊天、密钥或账单细节。
5. 提交前分别检查暂存文件、文档分类、相对路径/图片和章节锚点。不能只检查工作树目标存在，因为本地文件可能没有被Git跟踪。

从新提交取消跟踪只改变分支当前文件树；推送后旧commit、标签、分叉或缓存仍可能保留历史内容。历史清理、强制推送、标签和Release修改需单独明确安排，普通文档整理不执行这些操作。

仓库展示参考[GitHub README及相对链接说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)。社区入口按现有贡献、安全及行为文件维护；没有项目级开源许可证时，不把公开源码描述为已授予开源许可。
