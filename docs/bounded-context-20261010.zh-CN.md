# Umi 有界活跃上下文：实现与阅读记录

> 2026-10-10。实际源码：E:\SOME_SEVEN_PROJECT-57\Umi_v2.0。本轮保留已有修改和学习注释；使用隔离数据与替身模型，无付费模型调用、生产会话库操作、产品窗口启动或发布。

## 行为变化

旧实现不允许用户消息退出活跃窗口，每轮要求索引也列出全部用户输入。多次长输入会使用户原话本身超过预算，压缩 assistant/tool 无法解除。

新策略 `bounded-v1` 将永久历史与活跃请求分开。最新用户消息保持完整；另保留最多六条短旧原话，合计最多 4096 字节且不超过输入上限的 8%。其余旧消息可按完整消息组折叠。折叠不删除或修改原消息，不撤销要求，也不改变授权。

| 契约 | 实际实现 |
| --- | --- |
| 用户原话折叠 | MaintenancePlan 明确携带 projectionVersion；旧清单不带该字段，继续禁止归档用户原话。新清单拒绝最新输入、错误哈希和半工具组 |
| 可追回要求 | 清单保存全部折叠用户消息的 ID、原始 payload 哈希、顺序、内容字节数和原话片段。加载时与原记录重新核对；不接受模型编写的要求索引 |
| 活跃索引上限 | 最多 12 个原话来源，保留首条与最近三条，其余按当前文字相关性及限制词定位选择。每个来源最多五段 UTF-8 摘录；这不是完整语义要求提取 |
| 工具输出投影 | 长结果转成首尾摘录，保留 tool_call_id；调用及全部结果仍成组。记录原消息 ID、哈希、字节范围和截断说明，raw reasoning 不变 |
| 其他上下文 | 来源列表最多 32 项、笔记最多八项且文字明示缩短；运行态附件列表最多 16 项并提供总量。权限和真实运行状态继续由宿主提供，过大时阻塞 |
| 本地维护 | 新折叠用户原话使用本地索引与抽取片段，不请求摘要模型。其他 assistant 历史仍可使用已有摘要路径；每 run 最多四次模型维护尝试 |
| 提交与恢复 | 计划先保存，提交核对 lease、源指纹和窗口版本；取消、新更正或事务失败不能发布过期窗口。冻结请求保留投影版本和工具摘录证据 |

新增 `list_user_requirements`：分页查看全部已应用用户消息定位，含折叠状态和附件引用。`search_history/read_history` 读取原始消息，`read_work_memory/read_artifact` 读取模型记录及清单。未展示不等于撤销；`record_requirement.supersedes` 仍只是候选关系，不能授予权限。

## 沿代码理解一轮请求

1. [ContextManager.project](../packages/agent/src/context/manager.ts#L48) 建立稳定 persona、旧摘要、活跃完整消息组和有界状态尾部。工具结果的摘录仅影响模型投影。
2. [bounded.ts](../packages/agent/src/context/bounded.ts#L9) 负责 UTF-8 范围、原话定位、短原话保护和工具结果摘录。限制词只用于定位真实文字，不是授权分类器。
3. [prepareTurn](../packages/agent/src/context/manager.ts#L194) 在压力下按组选择退出窗口的消息；最近六组是偏好，硬预算时可以退让，最新输入及明确保留来源受保护。
4. [MemoryRepository.start/finish](../packages/adapters/src/sqlite/memory.ts#L260) 保存不可变计划、核对来源，再在事务中生成原话索引、摘要/清单资料和 window_committed 事件。
5. AgentEngine 从新窗口准备模型请求；SqliteStore 保存实际请求与 context artifact。图像投影额外保存原始 payload 的 sourceHash，不能把拼入图片后的请求载荷误当原消息哈希。

不新增数据库表，不修改历史迁移 SQL；复用原有不可变 artifacts 与窗口事件，新清单使用可辨识的投影版本。新代码能读取旧清单；旧程序不保证能读取含折叠用户原话的新清单，降级需要对应的数据兼容安排。

## 当前限制

- 最新单条输入或明确保留内容本身超过预算仍会阻塞，不静默裁剪原话；可使用已有文本附件入口按需读取。
- 索引是字面定位和原话摘录，不能保证模型识别并追回每条历史约束；主观理解、长任务成功率和旧图片再次视觉理解尚未做真实模型验收。
- 预算仍是 UTF-8/图像保守估算，真实服务端超限属于另一种证据；工具规格或真实运行状态本身过大也不会自动删掉以伪造可执行状态。
- 历史在 SQLite 中完整保存，当前读取/核验仍会遍历历史；大量历史的本地索引与性能优化可后续单独测量。没有新增 FTS、embedding、目标验收器或 OS 沙箱。
