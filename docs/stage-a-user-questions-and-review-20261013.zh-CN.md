# Umi 阶段 A：用户问答、冻结审阅与交付收尾（2026-10-13）

## 当前契约

按本次用户更正，**权限请求期间暂不提供自定义输入**，保留允许/拒绝和既有批准核验；也不显示停止按钮。Composer 保持独立 `approvalPanel` 插槽，以后需要时再扩展。新增的用户问答使用另一个 `questionPanel`，不能成为批准入口。

Agent 对影响结果的歧义或偏好，可自主调用 `ask_user_question`；一次 1–3 问，每问 2–6 个选项，每问均支持自定义回答。用户必须明确选择或填写再提交。能够查证的事实直接用工具调查，问答不是每个任务的前置步骤。实现参考 [OpenCode 的 question 工具](https://opencode.ai/docs/tools/#question) 的任务中提问用途，沿 Umi 既有循环落地。

## 已实现的行为

### 问答

- 当前模型工具执行后持久化 `question.requested`，前端自动展示问题卡。等待没有 60 秒工具超时；不再请求模型，只读取有界的原问题状态并响应停止信号。
- `answer_question` 经固定桌面协议进入原应用服务，验证会话、原执行、问题和选项；选择答案由宿主根据原选项规范化，自定义回答去除首尾空白。相同回答再次提交是幂等确认，不重复执行；不同的第二次回答拒绝。
- `question.answered` 是 user 事件，答案作为原工具配对结果交给模型。回答不创建 approval，也不授权宿主命令、文件交付或旧待执行操作。
- 停止、新输入或中断让待答问题即时失效，迟到回答不能重新启动任务。原答案和问题保留；恢复核验已回答事实，不重新弹问或猜用户答案。
- 问答复用现有已测量高度的底部区域。自定义文本及提交按钮不会被悬浮输入器覆盖；问答等待有一个“停止任务”入口，权限卡没有该入口。隐藏输入器的旧草稿不能因 Enter 被误提交。
- 开发者 JSON CLI 同样支持 `answer_question`，并声明 `userQuestions: true`，不会出现工具能问而终端没有回答命令的问题。

### 冻结文件审阅

- 新只读命令 `preview_change_file` 绑定 conversationId、changeSetId、具体 path 与 before/after/diff。原文读取冻结 blob，不读取后续变化的工作副本。
- 三种视图均支持 UTF-8 连续分页，返回真实范围、总字节和下一段。起点切字符或窗口容不下一个字符时返回明确错误，不能无进展续页。UI 校验版本和连续范围再拼接。
- 对照先剔除相同首尾，变化段使用有界精确匹配；比较超过 500,000 个单元时显示完整删除/新增段，而非切掉中间。对照用于审阅，不是可直接应用的补丁。
- 二进制文件明确展示元数据与完整 hash，不假装文本对照。修改前/后原文均可追回；最近派生文本缓存最多一个对象且限 8MiB，超过缓存预算仍可读取，不静默省略正文。
- 原批准仍绑定完整冻结 ChangeSet。没有将 GUI 预览误作模型读取证据，模型可见范围/版本替换保护保留。

### 目标文件刷新

全环境修订改为轻量失效提示。只有当前工作文件 hash 变化才重读并重置页面；其他文件修改不清空当前已加载正文或滚动位置。探测按修订区分正在进行的请求，并处理首屏读取期间修订变化的竞态。附件与冻结版本仍按独立身份读取。

这是环境事件驱动的版本核对，并非新增 Windows 文件监视器。外部修改可以通过刷新或下一页的 expectedHash 核对发现。

### 打开已交付文件

- 桌面新增 `open_delivered_file` Agent 工具，以及冻结侧栏的“打开已交付文件”按钮；按钮仅在该文件已有成功交付回执时出现。
- 仅接受所属会话的原 ChangeSet 和其中的文件。读取权限、资源范围、成功逐项交付回执、来源根身份、当前内容 hash 和文件身份均核验；删除项、未交付项、来源已变、程序/脚本类型拒绝。
- Agent 工具按现有具体批准执行。UI 按钮是用户明确打开该文件的动作。两者只使用系统默认应用打开文档、HTML、图片等支持类型，没有通用宿主程序/参数入口。
- utility process 通过固定且校验的文档请求交主进程，主进程在 `shell.openPath` 前再次核对身份和版本。系统打开与普通 Windows Job 命令生命周期分开，不依赖 PowerShell/Add-Type，也不因命令 Job 结束关闭用户应用。
- 结果仅证明系统接收打开请求，不证明窗口已呈现或 HTML 排版正常。打开前核验失败、系统明确拒绝均为已知失败，不留下未决状态卡住后续任务；回执丢失或无法确定是否执行时保留未知，不自动重复打开或关闭应用。停止可撤销等待；已经送入系统的打开动作不能保证撤回。
- 现有任务签收增加 `document_open`，绑定已知 mountId/path，再核验原打开工具、对应交付、系统回执与当前来源版本；当前文件变化后旧证据失效。它不能替代 HTML 排版的 review，也不以打开请求证明全部用户要求已完成。
- JSON CLI 当前不注册系统打开工具，明确声明 `nativeOpen: false`；桌面通过可注入的 DocumentOpener 提供能力，测试使用模拟端口。

设置页“插件”改称“执行环境”，说明 Docker/WSL 只供 Agent 通过具体宿主命令使用，不表示 Umi 已托管或自动切换后端。
