## 核心保持小，边界说清楚

当前唯一 AgentEngine 和 ToolExecutor 管授权、派发及恢复；文件工具管理具体对象，来源交付管理冻结变更集；Windows V1 管真实进程、Job、挂起复核和输出。宿主命令在当前用户权限下运行：批准和 Job 不限制其全部文件/网络访问。产品需清楚告知这份授权实际允许代码执行，不能把 cwd、副本或提示词当作沙箱。

明确对象上的文件操作可连续执行；读取版本过期时给模型可恢复反馈，不重新弹无关权限。来源交付与宿主命令保留具体批准。暂不新增“默认全自动”或按 Shell 语法白名单承诺安全；脚本、工具链和子进程的行为不能靠命令字符串可靠推断。系统拒绝不可被另一工具绕过；模型指引本身仍不是 OS 强制阻止。

## Docker 与 WSL2 的真实前提

Docker bind mount 默认可写宿主路径，readonly/ro 才限制该挂载的写入。Umi 后端应只映射冻结输入和专用工作/输出目录，核验实际 Mounts；不挂整个用户目录、凭据或 Docker 控制 socket。镜像/依赖/网络/资源与取消仍需独立验证，这些是待验收要求，本轮未实现。[Docker 官方挂载说明](https://docs.docker.com/engine/storage/bind-mounts/)

WSL 默认自动挂载 Windows 固定驱动器并支持启动 Windows 程序，Windows PATH 也可被加入 Linux PATH；仅在 WSL2 里运行不等于看不到宿主文件。关闭自动挂载仍可手动挂载，不足以单独证明隔离。普通 WSL 可以提供 Linux 工具链；要声称任务范围隔离，还需专用环境、互操作/挂载/网络和权限验证，不能为实现插件直接修改用户日常发行版或全局配置。[微软 WSL 配置说明](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)

能力应区分“提供 Linux 工具链”和“强制文件/网络范围”。Docker 或 WSL2 的名称、安装成功、一次 Node 启动都不是完整证明；不满足强制策略就拒绝该策略或明确提供不同的宿主批准路径，不伪装成自动降级。

## 只在真实替换点扩展

现有 [ToolModule](../packages/agent/src/tools/modules.ts) 用显式工厂依赖；[Windows V1 端口](../packages/adapters/src/host-process/port.ts) 保留挂起门控；[中立 ExecutionProvider](../packages/agent/src/tools/execution-provider.ts) 分离 plan、locator、observation。新后端应注入这里，不改循环或把数据库/批准写权限交给插件。

中立端口目前只是可选注入契约与测试替身，没有生产 Docker/WSL 实现；filesystemMapping 强制范围未知会拒绝，gated 模式也因缺可信 ready/recheck/release 而拒绝。不能直接把普通 WSL 包装成 enforced 来满足 schema。进入实际适配阶段先评估是否需要单独区分工具链后端与隔离后端；以真实需求扩展最小字段，不在本轮重写协议。

| 后端进入产品的证据 | 必须明确观察 |
| --- | --- |
| 身份与批准 | 后端版本/实现、程序或镜像、冻结输入与策略；实际启动定位；批准后变化不启动 |
| 文件与凭据 | 允许路径可读写，范围外哨兵/只读来源拒绝，联接/子进程不能绕过；无真实密钥 |
| 网络 | 若宣称禁止则实际拒绝受控连接；允许联网时说明权限，不能用“没发请求”证明禁止 |
| 生命周期 | 取消处理后代；启动后/写输出后/回执前故障，重启只核验原 locator；不可用保持未知 |
| 输出交付 | 内容 hash/大小/类型/来源与具体导出回执；不以 stdout 或退出码代替交付 |
| 效率 | 两类实际任务的成功率、准备耗时、执行耗时、批准次数和恢复成本 |

AppContainer/LPAC、Windows Sandbox 仍可作为未来研究参考：[AppContainer 官方实现](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer)、[Windows Sandbox 系统前提](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/)。本轮没有新实验。先前读到的机器配置和缺失命令只属于上一阶段观察，不当作本轮重新核验。

直接编辑来源、扩大自动宿主执行、联网安装或改变交付权限等重大行为，先列具体收益/范围/验收与用户协商。当前优先把成果路径、依赖准备和现有执行反馈做完整，不引入万能 FileService、服务容器、权限 DSL 或插件市场。
