## 打开动作的批准与旧读取权限分开

`delivered-open.ts` 将持久交付引用、批准前元数据观察、批准后版本核验分开：

1. `deliveredReference` 从当前会话环境的 ChangeSet、旧挂载和成功逐项回执中解析来源根、相对路径及期望hash，不接受模型给出的任意宿主路径。
2. `plannedDeliveredTarget` 只检查根、链接和文件identity，不读取正文。当前打开批准绑定该对象和交付hash；不要求原run的读取授权，也不恢复通用read/edit能力。
3. 获准后 `deliveredTarget` 读取hash；执行与主进程再检查当前对象。内容变化拒绝打开，等待中identity变化使旧批准失效，当前对象须重新批准。
4. 手动打开按钮继续沿现有固定IPC和用户点击入口，不借用Agent批准或任意Shell。

跨run、重启及重新发现得到新resourceId后，都可以继续使用原changeSetId打开交付对象；不必修改文件、重新交付或复制新副本。打开前失败/系统明确拒绝仍是已知失败；派发后回执丢失保持unknown，不自动重放。`document_open`只表示系统接收指定当前文件的打开请求，不证明页面排版。

旧编辑与交付权限的生命周期没有放宽。默认应用可以自行处理HTML/文档内容；该动作入口不是外部应用的网络或代码沙箱。

## 停滞阻断与正文收尾分开

原同名同参数阈值、read版本豁免、用户拒绝与unknown门控保留。第四次等价请求不执行，工具结果新增宿主产生的 `TASK_STALLED` 和当前原话inputId。唯一循环转入 `stalled-finalization.ts`：

- 闭合同批尚未派发工具的cancelled结果，保证工具消息配对；不再派发新操作。
- 在现有finalize阶段投影完整消息组，工具表为空，最多一次模型总结，输出上限4096、超时至多30秒；不额外请求模型维护上下文，不做模型重试。
- 编码超预算、模型错误、空正文或违规工具调用时，保存本地确定性说明。其为真实assistant历史消息与 `run.failure_summary` 事件，不冒充模型响应、不增加虚假计费usage。
- 保存过总结请求即视为已用机会；重启/恢复复用完整正文，或采用本地说明，不再次请求模型。正常模型总结保留真实usage、耗时和请求诊断。
- 新消息、停止、租约变化继续交给原循环处理；旧受阻正文绑定原话，不能遮住后来完整答复。
- 收尾完成提交 `run.failed(TASK_STALLED)` 和 blocked验收报告，不调用成功结束来冒充用户目标完成。既有检查点和验收项不删、不降低。

新增失败事件的messageId为可选，旧事件仍可重放；新增本地说明事件与现有SQLite事务共存，不新增数据库表或迁移。

## UI 文案
