# 直连 Search 与真实 API 验收（2026-10-18）

本轮将既有搜索切换为 DeepSeek Search 原始 JSON 接口，并用有限真实调用验证 Search → Fetch → 本地补读 → 正文答复。沿唯一 Agent 循环、ToolRegistry/ToolExecutor、现有 SQLite artifact、上下文维护与桌面工具行接入；没有新建数据库表、调度器或搜索设置页。前轮模型标签、Fetch 及全部未提交修改保留，本轮不提交或推送 Git，不更新 GitHub Releases/Setup 安装器，不操作生产会话。

## 搜索发生了什么变化

原 deepseek_server_web_search 通过 Anthropic 兼容 messages 接口，让额外的 Flash 模型带服务端搜索再生成答案。现在保留工具名和 query 参数，直接 POST /v1/tools/search，Bearer 鉴权，只发送查询、条数和 need_content=false；无需为这次搜索另发模型生成请求。主 Agent 仍负责阅读结果、决定抓取和最后答复。

官方 Search 支持结构化结果和搜索操作符；query 为1～128个 Unicode 字符，count 为1～50，默认10。[官方接口](https://api-docs.deepseek.com/zh-cn/api/search/)。Umi 初期选择默认5、最多10条，拒绝全空白或超长查询而不静默截短。运行时按 Unicode 码点校验，emoji 不按 UTF-16 两个字符误算；保留 site:/引号/日期等查询语法。

旧历史工具回执保持原样，模块版本为 umi.search 2.0.0。旧的6000字搜索参数不再符合新接口规格，重新执行会明确拒绝；不悄悄退回旧模型包装接口，也不自动重放旧派发或批准。

## 摘要、完整回执和网页正文分开

| 层次 | 模型先看到什么 | 可否追回 |
| --- | --- | --- |
| 搜索视图 | 默认最多5条标题/URL/摘要、时间、评分与来源；每标题最多200、摘要最多800个Unicode字符，整份来源视图为16KiB以内 | 被截字段、未展示条目及提供商其他返回字段保存在独立 web-search artifact |
| 搜索快照 | 工具反馈仅持有 snapshotId，标明 archiveTruncated、resultsTruncated 与各字段截断标志 | 使用 read_artifact(artifactId=snapshotId) 按 nextStartByte 续读，最大64000字节；偏移相对于规范JSON |
| 网页抓取 | Fetch 仍先返回最多8192字节正文及有界目录，不把完整正文暗藏在 data | 使用 read_webpage 定位或续读已存 Markdown，偏移相对于正文 |
| 原始网站 | Umi没有收到的动态/省略内容 | 这份快照不能补出提供商未返回的内容，也不证明浏览器画面 |

搜索响应及含元数据的规范快照均限4MiB；超过就明确失败，不保存一个冒充全文的前缀。存档保存收到的结构化JSON值，不声称保留原始HTTP字节、响应头或键顺序。need_content=false 不请求页面全文；如果提供商额外返回正文/字段，也只存档，不自动加入模型反馈。成功且非空才标明搜索来源 found；合法空数组是 succeeded + empty，格式错误、认证/余额/限流/网络失败则明确 failed。

成功快照沿已结算工具回执关联当前会话，其他会话拒绝；支持重启后无联网配置阅读、历史检索找回引用及有来源笔记。沿用不可变 artifact 和哈希核验，不新增数据库迁移。搜索摘要是提供商生成的资料线索，不是原文或事实证明；评分也不是可信保证。必要时抓取原页面交叉核对。

## 真实验收范围与结果

用户允许有限真实API。验收只使用公开官方文档、内存中的环境变量凭据和独立数据目录。预算包装器在发送前持久记录请求次数，跨脚本重跑仍受同一上限约束；固定官方端点，不记录鉴权头，不改Windows全局代理或生产配置。

| 请求 | 硬上限 | 实际 |
| --- | --- | --- |
| Search | 3次 | 2次，均HTTP 200 |
| Fetch | 3次 | 2次，均HTTP 200 |
| 模型 | 6次 | 3次，均HTTP 200 |

每次模型输出最多2048 token，请求体最多192KiB；本次仅测试 deepseek-flash、thinking=off，不将测试预算改成产品全局限制。真实服务返回的 model 字段为 deepseek-flash，没有返回1017日期版号；具体版本显示仍依据官方公告，不能把该字段冒称为后端权重版本证明。

第一部分使用固定测试模型驱动真实 Search/Fetch，通过产品循环保存回执。第二部分使用真实 DeepSeek 模型自行生成工具参数：调用搜索、抓取官方指南、read_webpage 查找“计费”，最后答复按成功请求收费、空搜索不收费、count不影响单价，并附官方链接。未替模型伪造工具选择或最终回答。测试提示明确要求核对计费并在截断时补读，因此这证明一次指定任务能够完成，不证明模型对所有网页会自行发现每个遗漏。

收到的 Markdown 为9352字节，首次8192字节预览确实截断。“计费”标题位于8094字节；补读覆盖预览末尾之后的条款，完整正文回读与保存哈希一致。更大的中文/emoji/CRLF文档、中部/末尾事实和多页无损追回由离线回归覆盖；这次真实文档不需要64000字节以上多页，不能冒称做了真实超长站点基准。

三次模型输入分别15382、20039、20805 token，输出分别118、102、300 token；累计输入56226、输出520，包含重复历史/前缀，并非唯一资料大小。其中缓存命中35584、未命中20642 token。完整工具表和系统上下文本身有成本；按需阅读减少无关正文，不能保证“上下文零噪声”或无限长任务不丢注意力。

官方公布 Search/Fetch 各5元/千次成功非空请求；本次4次请求的工具名义费用合计0.02元，另有模型费用，实际以提供商账单为准。没有查询账单/余额，也没有把部分客户端服务端工具促销视为Umi直连接口免费。[官方指南](https://api-docs.deepseek.com/zh-cn/guides/search/)、[2026-10-17公告](https://api-docs.deepseek.com/zh-cn/news/news261017/)。

## 错误、网络与剩余限制

搜索沿既有 network 工具语义，没有另加每次批准卡。HTTP 400/401/402/403/404/408/413/429/5xx 有明确诊断与可重试提示，但适配器不自动重试；30秒期限和用户停止会取消本地读取。取消/客户端超时不证明服务端没完成或没计费。原生宿主命令的批准机制不变，仍没有OS文件/网络沙箱；这里的公开网址检查不能约束Shell或保证完整DNS/跳转审计。

只接受有效结构化来源；明显私网、本地、认证链接不会被当成公开网页继续抓取。网页文字仍是资料，不授予权限。离线测试证明工具不会自行执行页面文字，不是对真实模型提示注入抵抗性的全面测试。

目前没有全局资料自动清理、产品级日/月费用硬限额或跨所有模型/宿主命令的网络预算。正文/回执仍有大小上限，现有默认24轮不保证一次读完4MiB搜索回执或2MiB网页。应按题目定位相关范围；全文任务分章节记录来源，必要时跨轮继续。不能将未读范围写成“全文没有”。
