# Umi 前端展示与直接答复修复

## 发现与修复

1. 新 Timeline 缺少原消息宽度容器与 footer，导致正文贴边、消息间距过小、悬停时间丢失。恢复 message-stack、统一消息与输入框最大宽度，恢复用户和最终回复的时间与复制按钮；悬停不改变占位高度。
2. 右侧首页按钮没有使用原 work-panel-body / work-action。恢复居中卡片、原有圆角与阴影；文件标签和打开文件位置按钮接入一致样式，保留拖动调整宽度。
3. 活动展示按 reasoning、工具开始与正文的持久顺序形成分段。正文是自然进展边界，思考和工具收进可展开详情；完成后总体收纳，最终正文独立。不再播报轮次与操作数量；原 turn / attempt 身份不变。
4. 字体使用 Windows 中文界面字体与系统无衬线字体；正文 15px、活动 12.5–13px；常规代码与内部状态用中性色，仅可点击文件与网址保留克制的链接色。
5. 旧引擎对无工具答复仍强制追加总结请求，最新运行状态因此容易被复述。现在无工具的完整响应经待应用输入、未知工具和执行租约核验后直接完成。有工具的任务仍先结算、等待批准，再进入原总结路径。没有寒暄分类器或第二套 Agent。
6. 唯一事件归约器从 run.completed 的 messageId 定位完整响应，把该响应的正文投影为最终正文。中断片段不能被提升；时间直接来自既有事件 occurredAt。没有新增数据库表或事件种类；实时与历史使用同一归约。
7. persona 提示词版本升级为 umi-persona-5。纯寒暄简短回应，不输出挂载身份、未执行操作清单或能力介绍；长任务以具体发现与下一步给出进展，保持工具结果和交付权限的事实边界。

## 验证

- TypeScript 编译及桌面资源构建通过。
- 137 个自动案例全部通过：原有 132 个，新增 5 个直接答复、分段、拒绝与实时/历史一致性案例。
- 现有 Umi.exe 桌面包 18 项检查通过。
- 真实 Electron 开发窗口 18 项检查通过，覆盖消息与输入框宽度、悬停时间节点、右侧卡片、分段正文、批准阻塞与已有恢复链路。
- 提示词迭代进行了 6 次真实 DeepSeek 请求。最终版本的寒暄与两句解释各只请求一次模型、零工具调用；证据见 evidence/ui-response-deepseek.json。
- 系统回收站测试在受限运行环境不能读取完整系统回执；正常宿主权限下的专用临时文件复核通过。未修改回收站实现。

## 使用与边界

源代码与现有 release/Umi-win32-x64/resources/app 应用资源已同步。退出并重新打开 Umi，使主进程、Agent 与页面加载同一版本；也可运行 npm run dev。

已有历史回复保留原文，新回复使用新版提示词与直接完成路径。长任务的阶段说明由模型生成，前端按真实事件展示，不自动编造进展。真实 API 验收覆盖 Flash normal 的简单交流；没有据此宣称复杂任务的语言或内容永远符合预期。

现有 Umi.exe 应用资源采用原打包方式更新；可执行程序及 Electron 版本未改变，会话数据库和工作副本未被迁移或清理。
