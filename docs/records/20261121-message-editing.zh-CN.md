# 已发送消息编辑（2026-11-21，纳入0.3.3）

用户可以原位修改已发送的用户消息，并从该位置重新继续。界面只呈现一条当前对话，不提供版本树；编辑不会恢复文件，也不会撤销已经执行的命令、进程或外部效果。

## 用户可见行为

- 用户消息的操作栏提供编辑入口，打开时填入原文；支持取消、重新发送及 Ctrl/Cmd+Enter，输入法组合期间不触发快捷提交。
- 提交时先停止并等待当前任务结算。未决工具、未知效果或未结算文件意图会阻止修订；不会把它们从视图隐藏后重新执行。
- 修改后的消息替换当前视图中的所选消息；后续旧聊天退出界面和模型上下文。修改前的文件、工具回执和原始消息继续保存。
- 首版编辑范围是消息文字，附件字节不变。为新消息复制附件身份与归属，复用不可变正文资料；旧消息的附件归属保留在原始历史。
- 编辑框采用一体式蓝色气泡，文字区域透明无边框并随内容增高；提示与按钮位于同一页脚，窄窗口自动换行，无额外阴影。简短提示后续聊天会被替换、实际效果保留，不增加独立确认流程。界面文字支持中英文，不翻译用户文字或历史标题。

## 输入、存储与当前视图

固定 IPC `edit_message` 接收 conversationId、commandId、targetMessageId、expectedLastMessageId 和 text，调用既有 UmiApplication，再进入唯一 AgentEngine。模型没有消息编辑工具，也不能借修订扩大权限。

commandId 的幂等指纹包括编辑类型、原消息、预期最后用户消息和新文字。重试返回相同回执，不重启完成任务；同 ID 不同内容拒绝。提交前及事务内检查当前消息身份和最新用户输入，避免旧页面覆盖新要求。

DB13 增加 `message_revisions`。新 run、新消息、`input.revised` 事件、修订区间索引、附件归属和命令回执在同一事务中保存；失败全部回滚。原 messages/events 不改写，DB1–12 的迁移指纹与旧事实不重写。旧程序拒绝此格式。永久删除会话/工作区仍为原子操作，并清理修订索引，保留真实源文件。

用户消息按接收位置确定当前视图，模型消息按已应用输入边界确定上下文。排队输入跨越工具组时，完整的 assistant/tool 组一起退出视图，不能留下半个工具配对。实时批次即使在新消息与修订事件之间分页，也须与完整快照、冷重放收敛到同一状态。

SqliteStore.messages、userMessages、历史搜索、按 ID 读取和 Agent 附件检索使用当前视图；originalMessages 及原始事件保留内部审计来源。Timeline、过程条目、历史导航和通用展示投影使用相同修订区间。

## 上下文、执行事实与权限

修订推进上下文窗口版本，清除当前摘要/折叠清单引用、当前笔记与任务投影，旧 carry 不再复用。原资料仍保留，但旧记忆/上下文派生资料不能由当前 read_artifact 作为有效资料重新读取。此前退出视图的模型请求也不再提供“模型已见文件原文”的证据；需要修改时重新取得有效读取依据。

宿主事实说明当前对话已修订，文件和命令效果没有撤销。`list_revision_executions` 分页提供原执行身份与状态，现有 `inspect_tool_execution` 只核验原操作；这些事实不构成当前用户要求或新批准，不自动重放旧任务。

旧 run 标记为退出当前对话，不能重新 claim、resume 或沿用旧批准。新任务使用新执行身份，任务内命令许可不跨修订复用；工作区目录授权按原生命周期保留。项目配置、Skill 和模型不因编辑消息取得额外能力。原生命令仍没有 OS 文件或网络沙箱。
