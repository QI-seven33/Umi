# 事件正文分块与直改边界修复

日期：2026-10-23。适用于未发布开发源码，package仍0.2.1、persona-25；数据库增量升级到10。不包含安装、打包或发布。

## 实现契约

流式模型可能产生大量单字片段。原先每片都保存完整事件JSON，事务缓冲只减少提交次数，没有减少重复外壳。现在仅在SQLite适配器内压缩新批次正文，唯一Agent循环、事件协议、归约器和订阅接口保持不变。

- 新增`event_blocks`及不可修改触发器，迁移10不改写旧事件、旧批准或迁移1–9的指纹。
- 新格式库需要支持DB10的程序读取；旧程序会拒绝该版本，不能把旧程序直接读新库当作已支持的降级路径。
- 每批沿原租约和归约校验生成逻辑事件；2–64条且序列化正文不超过2MiB时，完整事件数组独立deflate压缩并校验SHA-256。单条和超大批次继续原标量格式，不新增文本拒绝限制。
- `events`仍保留每条事件的原始身份、幂等键、顺序及唯一约束；新正文保存内部块指针。片段内容、边界、`occurredAt`和所有归属字段完整还原。指针不进入模型或桌面协议；这一步不会减少逻辑事件数量，也没有删除逐事件身份索引。
- 块、所有身份行、序号和运行投影在原事务中共同提交；任一校验、压缩或写入失败整批回滚。不延长原流缓冲刷新时机，不把未提交片段作为持久事实。
- 正文读取校验编码、展开长度、摘要、事件Schema、连续序号及成员和索引身份；缺失或损坏时明确失败，不静默跳过。支持块内任意游标与64位序号，读取对象不共享可变缓存。
- 解码缓存最多8个小块，展开字节合计约2MiB；大块用后不驻留。该限制不代表整个会话投影或应用内存已有总上限。
- 工作区仍整组数据库原子删除。候选与存活资料引用扫描会展开块，事件行和正文块随同一事务删除；托管目录仍在提交后按原身份清理。未加入后台分批删除，没有降低同步等级、关闭外键或更改WAL检查点策略。

## 直改调用边界修补

- `recycle_file`的prepare/执行/核验入口共用控制目录排除，直接挂载复核当前授权，执行时复核批准；不能借宽目录授权申请回收应用控制文件。回收站仍使用系统回收机制，不产生结构化文件版本备份。
- 独立导出共用应用配置的全部控制目录排除，避免仅排除核心数据子目录。
- 新会话的直改身份和会话记录同事务创建；用户选定根身份固定后再授予目录权限。根被替换、授权失败或进程中断，不能退回旧物化流程。失败可能留下无权限的直改草稿，可重新选择授权或删除；不宣称文件系统和数据库共同原子创建。
- 直接模式的发现提示改为当前可用的`request_directory_access`，旧副本保留旧提示。
- 任务许可自动复用的`approval.decided`标记为system来源，显式用户决定仍为user；不改写旧历史。

## 本轮验证

- 最终完整核心套件766项通过，包含64位分块序号、事务前置条件及分块专题10项；真实Electron隔离窗口110项通过。
- 真实子进程硬退出：已提交块完整恢复，成员插入中途未提交的块和身份行整批消失；重启仍沿现有中断恢复流程。
- 覆盖旧格式兼容、任意块内分页、Unicode/代理对、时间与身份、幂等冲突、写入故障、坏块拒绝、冷投影重建和共享资料回收/删除回滚。

## 剩余边界

网页搜索/抓取保持现行自动执行策略；查询词和URL可能携带模型已读文件的内容，尚无独立通用外传内容控制。配置模型也会收到进入请求的内容；获准原生命令不受OS文件或网络沙箱限制。后续外传设计独立讨论，本次没有静默改变联网策略。

请求/context资料仍可能跨轮重复保存完整历史；旧provider原始数组不自动压缩。会话投影`states`缓存仍按已打开会话积累，尚无通用淘汰策略或长期内存压力结论。新块缓存有界不代表这些问题已解决。

旧副本、冻结交付和未知结果的兼容分支有意保留，只在原语义入口可用；本次没有增加第三套工作模式。结构化读取的容量、分页、路径排除和根身份约束继续存在。离线回归不能证明付费模型理解所有自然语言恢复要求或所有真实任务成功。
