# 按需任务记录与仅思考响应的异常续作

日期：2026-10-22。当前0.2.0源码、DB7，persona升级为`umi-persona-22`。这是源码技术记录，不是发行包更新。前序见[流式接收修复](20261022-streaming-and-failure-guards.zh-CN.md)与[性能修正](20261022-history-and-preview-performance.zh-CN.md)。

## 触发问题与结果

此前persona要求复杂任务建立检查点、保存笔记、维护任务关系；已有未完成检查点还可能触发一次额外模型请求。这会使任务记录变成实际工作的前置流程，也可能对正常阶段答复重复追问。

本次把任务记录恢复为可选辅助，去掉按检查点未完成状态强制重答的分支。已有检查点、原始要求、证据校验及结束评估保留，未核验项不会因此变成通过。没有检查点的会话不再向模型注入空任务验收域。模型最终正文仍是语义判断，宿主不以此保证用户目标全部完成。

另一个独立异常是：模型以`stop`完整结束，却只给出reasoning_content，没有正文或工具调用。原实现会报错并暂停。本次在同一循环内补一次带具体宿主事实的续作，让模型继续必要操作或给出实际答复；再次出现则持久保存本地执行说明，不无限请求，也不把思考记成完成。

## 实现位置与契约

- `packages/agent/src/context/prompts.ts`：精简全局指令，任务/要求/笔记/Skill按需；按实际风险验证，不要求固定验证链。强调能推进时继续，受阻说明原因与剩余事项，进展承诺不代替最终结果。persona文件UTF-8字节约7061→3980；这是文本规模，不是计费token或准确率实测。
- `packages/agent/src/tools/tasks.ts`、`tools/memory.ts`与SQLite任务投影：同步工具说明和事实说明，避免一边说可选、一边仍要求每轮记录。参数Schema、来源/版本核对、证据与历史保持。
- `packages/agent/src/loop/engine.ts`：去掉检查点驱动的额外重答，已有检查点仍会提供事实及结束评估。正常答复不增加请求。新输入优先处理，不把旧空答复的恢复要求贴到新输入。
- `loop/answer-recovery.ts`：恢复依据来自最新已应用用户原话之后的持久消息、attempt完成状态和服务端stop原因；不依赖进程内计数。重启或同一输入的显式恢复不重置该异常机会。

此续作只针对完整stop、非空思考、空正文且无工具调用的确定形状；不按自然语言关键词判定“任务没做”。完全空响应、网络断流、length截断各沿原机制处理。用户停止、代次校验、未决宿主效果及显式用量限制继续生效。恢复请求没有新权限，合法工具仍按原批准链执行；思考中出现的文字或伪工具标记不被解析执行。

persona-22会使旧carry在下一次请求重建模型视图；原始历史和请求不改写，后续仍沿既有稳定前缀与增量事实机制。

## 取消与最终答复的真实边界

用户停止入口保留目标，这是已有行为，本轮补验了异常续作场景中的停止优先级。模型指令与set_task_state说明现在明确：询问进展、继续、暂时停止、遇错和无法验证都不是撤销目标；取消只用于用户明确撤销。

**本次没有新增通用语义取消授权器。** 任务状态入口仍验证最新真实原话及引用，不能机械证明一句话的取消含义。不能把提示加强写成“已从宿主保证模型不会误取消”。也没有加入第二Agent、词表判定器或根据思考文本生成工具调用。

## 同日后续：日志定位与交付说明的小范围修正

本次仅改3个现有产品文件，没有新增工具、依赖、数据库表、事件类型或Agent循环，persona仍为22。

`read_process_output`增加可选`find`：在本会话原执行的已保存输出中，按区分大小写的字面关键词从startByte定位首个匹配；返回附近有界原文、匹配的UTF-8字节位置、搜索范围和search.nextSearchByte，可继续找后续不重叠匹配。不传find时保留原分页。未命中只说明归档搜索范围无匹配；archiveComplete=false不能排除未归档内容。读取不连接实时进程，不重跑命令，也不增加批准。

变更集预览明确“冻结当前字节，不编译或构建”；交付及恢复回执只确认对应冻结字节的写回/满足，不暗示源码修复已进入成品或运行效果通过。没有加入自动依赖跟踪、构建器或强制验证链，因此忘记重建仍不能被通用自动阻止。

原失败HTML的诊断也向前推进：独立Electron运行原成品的逐字节副本，成功加载其Three.js依赖后，控制台持续在updateFauna→animate报告读取undefined的[0]，截图无场景；页面ready标记和canvasOpacity仍为真/1。另一个诊断副本只在鸟的userData重新赋值时保留原属性，场景能够显示，观察窗口内未再出现该运行错误。原成品、原源码及历史报告均未修改。

这确认了该样本的运行缺陷及最小修复对显示的影响，不是Umi重新自主完成任务的验收，也不覆盖动画全周期、交互和审美质量。诊断脚本、页面副本、日志与截图仅本地保存，不进入产品或公开文档。
