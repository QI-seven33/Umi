# 文件引用核验与直改文档打开修复

日期：2026-10-24。适用0.3.0之后的未发布源码；package仍为0.3.0、DB12、persona-25。本轮没有重新打包、安装、推送或更改已有Release。

后续版本归属：本记录实现纳入0.3.1，本版重新验证与交付状态见[0.3.1版本说明](../releases/0.3.1.zh-CN.md)。以下版本、日期、测试结果及“未发布”描述保留为当时记录。

## 问题与原因

旧正文链接仅按路径外形和mount定位，没有核实文件存在。单根工作区里的`msedge.exe`及`python -m http.server`会通过扩展名判断；简写`index.html`被定位到工作区根，无法找到已读过的`project/index.html`，旧CSS名、目录和错拼也会生成失败入口。

旧纯渲染用例只断言控件生成；既有Electron点击覆盖了已知根目录文件，未覆盖上述负例和子目录简写。这是验收覆盖缺口，不能用既有通过数量否认实际失败。

直改环境没有与旧`open_delivered_file`对应的系统打开工具，后者按契约只向旧副本开放。模型会转向`run_shell`启动浏览器；命令桥在父命令正常退出后也调用`TerminateJobObject`，不是只有停止/超时才清理。实际排查记录中的显式浏览器启动、等待后读到标题与随后`jobInactive=true`高度吻合此机制，但没有退出瞬间完整进程树，不能证明每次窗口关闭都只有这个原因。原始记录只留本地。

同一命令快照还确认缺少`ProgramFiles`类变量，导致常见安装路径探测误报；这是精简环境的兼容问题。

## 实现契约

- 先解析候选，再由固定`resolve_file_links`只读IPC核验当前会话的授权、范围、根/文件身份、普通文件及4MiB容量；只返回唯一现存目标。不读取正文、不授予权限、不递归扫描项目，不把未知file URL转给系统。
- 简写只从当前根及本会话近期128条成功文件工具记录补全；同名歧义保持原文，显式路径仍可定位。命令样式、程序/二进制名、不存在/旧文件、目录、受保护位置与链接不显示预览按钮。当前只对应工作文件的既有文本预览能力，不新增PDF/Office/图片正文转换。
- 每批至多32引用、256项候选元数据核验；客户端在一个文件事实代次去重并保留至多256引用，逐批查询。工具完成或授权变化换代，模型逐字流不逐字发IPC。外部文件变化不持续监听；点击仍走既有实时预览核验。
- 新`open_file`只接收直改mountId和相对路径，需本次独立host-code批准，目录授权/自动命令许可不代替它。prepare、执行及主进程重新核对对象；通过既有DocumentOpener与固定主进程通道交给系统默认应用，不向模型开放程序、参数、URL或持久服务入口。
- 旧副本保持交付打开规则；普通命令Job清理不放宽。停止或打开回执未知不会重新派发，系统接收不等于窗口、页面渲染或交互验收。
- 仅在既有命令环境白名单增加`ProgramFiles`、`ProgramFiles(x86)`及`ProgramW6432`，继续过滤密钥、NODE_OPTIONS和其它环境。本次不改变Windows设置或扩大任意命令最高权限。

协议只做纯候选定位/校验；宿主适配器负责权限与元数据；renderer只调用固定IPC并呈现核验结果。文档打开复用原端口与唯一Agent循环，无新后台执行者、Job脱离策略或系统沙箱。

## 实际验证

完整核心791/791通过；本轮真实Electron111项离线检查通过。实际点击Windows绝对文件链接后显示真实文件内容，程序名、复合命令与缺失文件保持普通代码；既有自然恢复、命令许可、工作区管理及删除路径仍通过。

独立临时文件任务覆盖子目录简写、绝对/URI/逻辑引用、空格中文、错拼、旧CSS、同名冲突、未知目录不扫描、硬链接/控制目录/外部路径拒绝，以及文件删除/撤销后的重新核验。客户端合并重复引用并验证批次与缓存上限。

实际Agent工具链确认独立打开批准、下次仍需批准、变更后重新询问/拒绝、撤销后不打开、禁止程序/argv/URL入口、未知回执冷启动不重放，并确认不创建process_executions记录。系统打开端口使用隔离替身，未操纵用户浏览器。

实际Windows原生子进程验证三项安装目录变量可见、合成API密钥仍不可见；无害心跳子进程已启动后，在父命令正常退出时确实被Job清理。没有启动真实浏览器或持久HTTP服务。

本轮未调用付费模型、未修改默认会话库。没有验证真实模型一定选择新工具、系统文件关联、实际Chrome持续运行、页面视觉/交互或新安装包。修复仅在源码，既有0.3.0资产与已安装程序未变。

接口事实参考：[Electron shell](https://www.electronjs.org/docs/latest/api/shell)、[Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。社区对照与原始调查稿留本地。
