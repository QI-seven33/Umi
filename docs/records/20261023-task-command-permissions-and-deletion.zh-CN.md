## 自动模式首版契约

采用中档定位：已授权目录内结构化读改继续自动执行；宿主命令首次明确询问。自动模式下，支持的具体开发命令可由用户在真实批准卡片选择“本任务允许重复”。“允许本次”保持单次语义，旧批准不自动升级。

首版候选只有单条`npm test`、`npm run test/build/lint/typecheck/check`，以及直接`node --test 文件…`。当前不复用额外参数的npm脚本、复合Shell、任意内联代码、安装/发布/外发/删除或无法识别的命令。已有preparation声明的命令仍逐次批准。命令名字不是安全证明；用户选择任务许可仍是在信任这条命令可执行随修改变化的项目代码。

匹配完整冻结程序身份/hash、argv或完整Shell文本、cwd身份和逻辑来源、环境、stdin、限制、桥接指纹及环境绑定。忽略新executionId、租约字段和普通文件修改造成的环境修订；每次执行仍生成独立身份和派发事实。所有工作区目录授权的身份/修订另行绑定，授权变化不复活旧许可。

许可只在同一实例、同一run、同一租约代次、同一最新用户输入及同一设置修订有效。新输入、停止/恢复、切换模式、重启、run结束、程序/cwd/授权变化均不继承旧许可。切回询问阻止后续复用，不声称撤销已经发生的外部效果；停止当前进程仍使用原停止链。

普通编辑许可没有扩大到命令、外发或发布。最高权限由固定用户入口签发，模型参数、项目文件和Skill不能选择task范围。没有完全访问模式，没有OS文件/网络沙箱。

## 调用与持久化

`ApprovalCard → 固定approve(scope) → DesktopService → UmiApplication → SqliteStore / CommandPermissions`。

Agent仍沿唯一`AgentEngine → ToolExecutor`。准备后需要批准时尝试任务许可；无匹配则沿原批准等待。`dispatch`与`assertApprovedExecution`都检查派生许可，原CommandTools执行及原生挂起进程释放前再次核验未删除。

许可和复用来源保存为不可变artifact，由原批准事件引用，没有新数据库表或新Agent循环。事件区分`decisionSource=user/task-grant`及来源批准，不伪造重复的人类点击。先保存待决定请求，再在事务中保存复用来源及allow；两事务间中断只留下待决定记录，没有命令派发。

首次测试发现嵌套事务导致复用失败，已经改为上述两阶段记录；这不是依靠去掉宿主批准检查让auto运行。复用来源保存失败时，第二条命令保持prepared、决定仍为空。

拒绝匹配按实际程序/参数/脚本/cwd/stdin检查，不再只在preparation存在时检查；添加默认参数外壳不能绕过同一具体命令的拒绝。迟到重发不能把单次批准升级为任务许可。

桌面输入框和设置页都可选择自动模式；批准卡片明确区分本次与任务许可，切回询问时隐藏任务许可按钮。文件蓝色沿原色相略提亮为`#2e74d7`，布局、欢迎语、侧栏和原主题保持。

## 删除热路径

沿原ConversationDeletion、SQLite事务、完成凭据及托管目录清理实现，没有新增后台清理引擎。

- 实际查询计划显示历史扫描选用了随机idempotency_key索引；改为按log_epoch/sequence读取，沿事件主键顺序取页。
- 用数组返回行，保留首次列名引用语义；简化ASCII资料ID扫描。规范JSON在核对有效性/hash后直接查引用，压缩协议、转义和兼容ID仍完整解码。引用已覆盖全部资料时不再无意义展开闭包。
- 大部分事件整组删除时顺序处理；同事务临时拆下Umi自有的两个JSON局部辅助索引，按原SQL重建。失败时DDL、数据与删除完成凭据一起回滚，外键及FULL同步不关闭。
- 实测没有带来收益的引用缓存和更大页缓存候选已撤掉；继续只在删除期间使用原64MiB建议缓存并恢复原值。

## 验收与剩余范围

构建、桌面构建和git diff --check通过。完整离线核心751/751、真实Electron离线桌面110/110通过；其中自动模式实际原生命令及故障场景10项，删除相关22项。桌面真实切换模式、点击任务许可、执行两次命令核对文件字节，新任务拒绝后无新增效果。

在同一份约800MB、430093事件的隔离一致性副本上，修改前后实测：

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 删除原大工作区，保留另一个工作区 | 32.73秒 | 13.41秒 |
| 删除最后工作区 | 9.53秒 | 8.13秒 |

这是本机单次仪器化样本，目录移除器只核验并计数；其它工作区和外键核对通过，原测试库不写入。不是Windows冷启动、p95或真实大目录移除的端到端时间，也未精确复现用户先前7秒。最后工作区剩余延迟仍明显，不能宣布卡顿完全解决。

已验证真实命令修改当前代码后的复用、单次不升级、参数/run/输入/模式/重启失效、原生释放前撤销及恢复不重跑、来源记录失败不派发；删除验证覆盖共享/压缩/Unicode引用、自定义列名、辅助索引重建及故障回滚。

已确认保留工作区整组数据库原子删除，不实施先移出列表再后台分批删除；既有托管目录在数据库提交后清理、失败重试的语义不变。约430093条事件中426420条是model.delta，流式分片的行/索引成本仍需单独研究；不通过丢历史或静默切换存储格式处理。额外隔离对照中，自动检查点下删除11.80秒、COMMIT占4.82秒；关闭自动检查点时删除8.09秒，随后检查点另需3.78秒。仅移后检查点没有消除总体工作量，本轮不采纳该设置变化。这些单次样本也显示磁盘时序存在波动，8.13秒不是延迟上限。

大库删除仍是同步事务。缩短耗时不能证明消除全部卡顿，也没有用清空用户库代替性能修复。大库结果不等于所有磁盘/杀毒/文件数量下的端到端延迟；托管目录真实批量移除另受文件占用影响。

普通操作与具体开发命令许可是自动模式首版的实际范围，不代表任意“看起来安全”的新命令免询问。没有付费模型验收或全面风险分类器，不能宣称自动完成所有任务或没有新bug。
