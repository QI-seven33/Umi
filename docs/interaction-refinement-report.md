## 重复正文的真实原因

截图中的两次完整天气回答不能单凭截图判定为重复点击。审查发现，核心在工具结束后，即使已经得到完整无工具正文，仍强制切换到一个新的无工具总结请求。于是先展示完整阶段正文，再展示近似的最终正文。

现在：工具调用全部结算 → 模型返回完整、无工具调用正文 → 检查没有待处理用户输入和未核验工具 → 提交完成事件 → 同一归约器把该正文归入最终回复。实时显示与历史重放使用同一事件，不删除事实、不在前端按文本去重。批准未完成、工具结果未知或响应中断时不会走这条完成路径。已有旧历史保留原始内容。

## 边界与兼容性

- 沿用数据库版本 5、原附件表和 artifacts，无新增表或迁移，不创建第二套 Agent，不新增 npm 依赖。
- 每条消息最多 8 个附件，单文件 1 MB；图片长边最多 4096 像素。文本转为 UTF-8 后同样受大小限制。
- PDF、DOCX、XLSX 等二进制文档解析尚未接入；添加时给出具体错误，不能声称已上传可读。粘贴按钮读取文本，图片粘贴使用 Ctrl+V。
- 图片会进入真实模型请求和请求快照；实际费用以 API 用量为准。完整历史图片仍受服务端 48 MiB 请求体上限，不能宣称无限制。
- 批准卡片展示冻结范围，批准后仍按原有交付流程核验。新增图片没有扩大文件、宿主命令或 IPC 权限。
- 归档不是删除会话文件。历史重复回复不做破坏性清洗。
